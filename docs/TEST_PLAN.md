# Приёмочные проверки

Автоматические тесты выполняются стандартным unittest; файл VALIDATION.md содержит фактический результат. Ниже — ручные сценарии для PostgreSQL и скриншотов при защите.

| Шаг | Ожидаемый результат | Кадр |
|---|---|---|
| Регистрация с паролем короче 12 | Отказ браузера или сообщение сервера | Форма регистрации |
| Вход student@demo.local | Личный кабинет и два курса | Кабинет |
| Прохождение 10 вопросов | Сохранённый результат 0–100 | Результат |
| Отправка домашней работы | Ответ виден ученику и преподавателю | Задание |
| Преподаватель оценивает работу | Ученик видит баллы и комментарий | Оценка |
| Вход student2, /course/1 | HTTP 403, событие access_denied | Отказ и журнал |
| Ученик открывает /analytics.csv | HTTP 403 | Отказ |
| В логин передать ' OR 1=1 -- | Вход не выполнен | Сообщение входа |
| В ответ передать script с alert | Текст без выполнения JavaScript | Страница ответа |
| Удалить csrf_token в DevTools и отправить | HTTP 400, csrf_blocked | Ошибка CSRF |
| Выход и повтор защищённого GET | Перенаправление на вход | Страница входа |
| Запуск seed | 5000 синтетических попыток | Аналитика |
| CSV в DataLens | Число записей 5000 | Дашборд |

Для Postman сначала GET /login: сохранить cookie и CSRF-токен HTML. Затем POST /login с form-urlencoded, тем же токеном и cookie. Аналогично получить новый токен из страницы защищённой формы после входа. Не отключать CSRF ради Postman. Скриншоты необходимо снимать с реально работающей системы, не заменять макетами.
